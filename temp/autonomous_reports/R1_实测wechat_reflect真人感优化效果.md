## 问题根因分析

### 1. 模型层（核心问题）
glm-4-flash 作为非推理小模型，对 prompt 约束遵守度差：
- **emoji禁令形同虚设**：base.md明确"严格禁止emoji和颜文字"，但52%回复仍带emoji
- **人设漂移严重**：选了"高冷毒舌破防"（2-5字冷淡），实际回复经常热情讨好
- **被挑衅时讨好**：被骂"sb"后仍回复"挺有趣的"，完全违背人设中的"怼人"规则

### 2. 代码层Bug
- **EXIT泄漏**：`[EXIT]` 是对话模式退出信号，被当作普通消息发送。应在发送前过滤 `[EXIT]` 字符串
- **无后处理过滤**：LLM原始输出直接发送，无emoji清洗、长度截断、AI味关键词检测

### 3. Prompt层
- base.md规则虽详尽，但小模型指令遵循能力不足
- 对话模式的prompt模板对安全信号(EXIT)处理不当

## 建议（按优先级排序）

### P0 - 代码级后处理（立即可做）
1. **EXIT过滤**：发送前检查回复内容，如果是 `[EXIT]` 或 `EXIT` 则跳过发送
2. **Emoji/颜文字清洗**：用正则移除所有emoji和日式颜文字
   ```python
   import re
   # emoji正则
   text = re.sub(r'[\U0001F600-\U0001F64F\U0001F300-\U0001F5FF\U0001F680-\U0001F6FF\U0001F1E0-\U0001F1FF\U00002702-\U000027B0\U0000FE00-\U0000FEFF\U0001F900-\U0001F9FF\U0001FA00-\U0001FA6F\U0001FA70-\U0001FAFF]', '', text)
   # 颜文字正则（常见的日式颜文字模式）
   text = re.sub(r'[\(（][^\u4e00-\u9fff]{1,15}[\)）]|[～~♡❤✧☆★♪♫♬♩]', '', text)
   ```
3. **长度截断**：插话>8字则截断到第一个句号/问号处

### P1 - Prompt优化
4. 在system prompt中强调："回复绝对不能包含任何emoji符号、颜文字、波浪号"
5. 对话模式prompt明确："如果回复是[EXIT]，不要发送，直接跳过"

### P2 - 模型升级（需用户决策）
6. 考虑换用指令遵循更强的模型（如 glm-4-plus）做回复生成
7. 或在glm-4-flash基础上增加few-shot示例（当前只有反面示例，缺少正面示例）
